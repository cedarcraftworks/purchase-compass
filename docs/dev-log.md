## 見つかった問題と対応

### 1. 「パン」が「パンツ」に含まれてしまう
- **気づいたこと**：キーワード辞書を作る段階で、「パン」を食品にすると「ワイドパンツ」まで食品に分類されることに気づいた。
- **原因**：日本語は単語の区切りがないので、部分一致が別の単語の中で当たる。
- **対応**：辞書を「食パン」「菓子パン」に変更。より細かいカテゴリを先に判定する順にした（「シャンプー 詰め替え」は日用品ではなく美容）。
- **再発防止**：この2例をテストで固定した。

### 2. 毎月買うコーヒー豆が「サブスク」と判定された
- **起きたこと**：同じ店・同じ金額・約30日ごとの購入を定期課金と判定するルールが、毎月同じ豆を買う行動にも当たった。
- **判断**：物を定期的に買うのは「買い時」の対象であり、「忘れている課金」ではない。
- **対応**：定期課金の判定を、サブスク・デジタル系と、カード明細の不明な支払い先に限定した。

### 3. おすすめが安い物ばかりに引っ張られた
- **起きたこと**：検索キーワードを購入回数で選んだら、コンビニのおにぎりやエナジードリンクが上位を占め、提案が飲み物に偏った。
- **対応**：
  - 回数だけでなく金額も重みに入れた（金額の平方根）。
  - キーワードは1カテゴリにつき1つまでにして、興味の幅が出るようにした。
  - 似ている度合いが低い過去の購入品は、理由として名前を出さないようにした（こじつけを防ぐ）。
- **確認**：実際の分析結果を見て調整し、カテゴリが分散することをテストで固定した。

### 4. 手元では全部通るのに、GitHub上のビルドだけ失敗した
- **起きたこと**：型チェックの途中でできた `.js` ファイルが `.tsx` の隣に残り、Viteが古い `App.js` を読み込んで本番ビルドが壊れた。
- **気づいた経緯**：手元ではlint・型・テストがすべて通っていたが、CIのビルドとDockerのジョブが失敗した。
- **対応**：ファイルを削除し、`.gitignore` に除外ルールを追加した。
- **学び**：手元で通ることと、まっさらな環境で通ることは別物。CIで一から組み立てる意味がここにある。

### 5. Dockerの中だけ設定ファイルが見つからなかった
- **起きたこと**：画面のビルドが共通設定 `tsconfig.base.json` を参照していたが、Dockerにコピーしていなかった。
- **対応**：Dockerfileでコピーするように修正した。CIでDockerイメージも毎回ビルドしているので気づけた。

### 6. デモの「買い時」が時間とともに全部「過ぎた」になる
- **気づいたこと**：デモデータを作る段階で、購入日が固定のままだと、数か月後にデモを開いたとき全商品が「とっくに買い時」になると分かった。
- **対応**：読み込み時に、最新の購入が2日前になるよう日付をずらすようにした。
- **工夫**：週単位でずらすので、曜日・時間帯の傾向は変わらない。

### 7. 公開デモで取り込みを試せなかった
- **起きたこと**：サーバー不要の公開デモでは、取り込みのプレビュー（サーバー側の処理）が使えなかった。また、どんな形式のファイルを用意すればよいかも画面から分からなかった。
- **対応**：
  - 取り込み処理（入出力のない純粋なTypeScript）をAPIから共有パッケージに移した。APIとブラウザが同じコードを動かす。
  - お店ごとの見本CSVをダウンロードできるようにし、デモでも読み取り結果の確認まで試せるようにした。保存だけはデモでは無効にしている。
- **再発防止**：配布する見本が元データと一致し、問題なく読めることをテストで確かめている。
