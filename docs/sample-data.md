# デモ用の購入データについて

公開デモとリポジトリに入っている購入履歴は、**すべて架空のデータ**です。実在の人物の購入履歴は1件も含まれていません。

この文書は、データの出所、作り方、そしてデモの分析結果をどう読めばよいかをまとめたものです。

## 概要

| 項目 | 内容 |
| --- | --- |
| 出所 | [`generate_samples.py`](../services/analyzer/scripts/generate_samples.py) が生成したもの |
| 人物像 | プログラミングを学ぶ大学生（架空） |
| 期間 | 約6か月（2026年4月20日〜10月20日。デモでは日付をずらして表示。後述） |
| 件数 | 199件 |
| 再現性 | 乱数の種（seed）を固定しているため、何度実行しても同じデータになる |
| 置き場所 | [`samples/`](../samples/)（取り込み画面から見本としてダウンロードできるのは `apps/web/public/samples/` の同じ内容のファイル） |

## なぜ架空のデータを使うのか

- **プライバシー**：購入履歴は個人情報です。公開リポジトリやデモに実データを置くことはしません。
- **再現性**：誰が動かしても同じ結果になり、テストとデモの見え方が一致します。
- **検証のため**：分析が「本当に見つけられるか」を確かめるには、答えの分かっているデータが必要です。下の表のとおり、各分析が見つけるべき行動パターンを意図して入れてあります。

## 入れてある行動パターンと、それを見つける分析

デモに表示される傾向・おすすめ・気づきは、次のパターンを分析が正しく拾った結果です。つまり**デモの結果は「当たるように作ったデータ」に対する結果**です。実際の購入履歴でどれだけ役立つかの証明ではない点に注意してください。

| 入れたパターン | お店 | 見つける機能 | デモでの表示例 |
| --- | --- | --- | --- |
| コーヒー豆を約25日ごと、洗剤を約46日ごと、トイレットペーパーを約34日ごと、プロテインを約30日ごとに購入 | 楽天・Amazon | そろそろ買い時 | 「いつもは約24日ごとに購入…」 |
| 本の約75%を22時〜深夜1時に購入。最近1か月に本の購入が集中する（就活関連を含む） | Amazon | 傾向（最近の変化）、衝動買い | 「直近30日の「本・マンガ」への支出は…倍」 |
| 深夜1時台に20分以内でイヤホン・ケース・キーボードを連続購入 | Amazon | 衝動買い | 「深夜1時台の購入 +30」「直前30分以内に2件購入 +25」 |
| 服とゲームをメルカリで購入 | メルカリ | 傾向（中古） | 「「ファッション」の100%はメルカリ（中古）で…」 |
| 平日昼にコンビニ、週末夕方にスーパー | 実店舗 | 傾向（時間帯・買う場所）、ヒートマップ | 「昼（11〜17時）の購入が最も多く…」 |
| 動画・音楽・クラウド・語学アプリの月額課金 | カード明細 | 定期的な支払い | 年間の合計金額つきで4件 |

## ファイル形式について

| ファイル | 想定した形式 | 補足 |
| --- | --- | --- |
| `amazon_Retail.OrderHistory.1.csv` | Amazonの「データのリクエスト」で届く注文履歴 | 列名は公式の出力に合わせていますが、実際のファイルより列は少なくしています |
| `rakuten_purchase_history.tsv` | 楽天の購入履歴ページの表をコピーしたもの（タブ区切り） | 楽天には公式のCSV出力がないため、利用者が表を貼り付ける場面を想定しています |
| `mercari_purchases.csv` | 購入一覧を表計算ソフトでまとめたもの | メルカリにも公式のCSV出力はありません |
| `store_receipts.csv` | レシートを手でまとめたもの | |
| `card_statement.csv` | カード明細のCSV | 実在のカード会社の形式ではなく、一般的な列（利用日・利用店名・利用金額）にしています |

- 商品名と価格は、それらしい値を手で決めたものです。実在の商品の価格ではありません。
- 店名は「珈琲問屋サンプル店」のように、架空とわかる名前にしています。
- 実在のショップの形式と細部が違っても、取り込み画面で列の対応を手で選べば読み込めます。

## おすすめ用の商品データ

楽天のAPIキーがない環境（公開デモ、CI、手元で初めて起動したとき）では、同梱の [`sample_catalog.json`](../services/analyzer/compass_analyzer/data/sample_catalog.json)（架空の商品49件）からおすすめを選びます。

- 商品のリンク先は、楽天市場の**検索結果ページ**です。実在の特定の商品ページではありません。
- 画面には「サンプルの商品を表示しています」と明示しています。

APIキーを設定すると、楽天市場の商品検索APIから実在の商品を取得します。その際、外部に送るのは検索キーワードだけです。

## デモでの日付の扱い

購入日がそのままだと、時間が経つほど「買い時」がすべて「とっくに過ぎた」状態になります。そのため、データを読み込むとき（[`seed.ts`](../apps/api/src/seed.ts)）に、最新の購入が「2日前」になるよう全体を**週単位で**ずらしています。週単位なので、曜日と時刻の傾向は変わりません。

公開デモ（GitHub Pages）は、こうして読み込んだAPIの応答を記録した [`apps/web/public/demo/`](../apps/web/public/demo/) を表示しています。記録の手順は [`snapshot-demo.mjs`](../apps/web/scripts/snapshot-demo.mjs) にあります。

## データを作り直すには

```bash
python services/analyzer/scripts/generate_samples.py   # samples/ と web の見本の両方を更新
```

見本ファイルが `samples/` と食い違うと、web のテストが失敗するようにしてあります。

## 自分のデータで使う場合

実際の購入履歴は `private-data/` フォルダ（Gitの管理対象外）に置き、手元で起動したアプリから取り込んでください。公開デモやリポジトリには含めないでください。
