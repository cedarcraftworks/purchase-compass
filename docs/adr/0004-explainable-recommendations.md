# 0004 おすすめは説明できる方法で作り、生成AIは使わない

## 状況
このアプリが持つのは1人分の購入履歴だけ。また「なぜそれが出てきたのか」が分からないおすすめは、信用されにくい。

## 決めたこと
- 購入した商品名を文字2〜3文字ずつ区切って数値化（TF-IDF）し、候補商品との似ている度合い（コサイン類似度）で並べる。
- 最近の購入・金額の大きい購入ほど重く数える。
- 最も似ている過去の購入品の名前を、理由として表示する。
- 似ている度合いが低いときは、名前を出さない（こじつけを避ける）。

## 検討した他の案
- **協調フィルタリング（似た人が買った物）**：他の利用者のデータが必要で、1人分では成り立たない。
- **生成AIに選ばせる**：費用がかかり、購入履歴を外部に送ることになり、同じ入力でも結果が変わるためテストしにくい。
- **深層学習の埋め込み**：精度は上がりうるが、モデルが大きくなり、理由を説明しにくい。

## 受け入れたこと
- 「意味は近いが言葉が違う」商品（例：コーヒー豆とエスプレッソ）には弱い。
- 改善の余地は、利用者のクリックを記録して精度を測れるようになってから判断する。
